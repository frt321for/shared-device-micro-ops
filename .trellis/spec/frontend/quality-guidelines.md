# Quality Guidelines

> IoT 项目前端代码质量标准

---

## UI/UX 质量标准（最高优先级）

### 设计质量要求

- **必须**参考 Design Reference（`H:\iot\Design Reference\`）中的设计风格
- **必须**调用 `frontend-design`、`ui-ux-pro-max` 等技能包
- **禁止**蓝紫渐变等千篇一律的 AI 风格
- **禁止**粗糙的 UI — 用户看重精美 UI 大于功能完整

### 响应式要求

- 必须支持 1920px（桌面）、1024px（平板）、375px（手机）
- IoT 监控大屏优先适配 1920px
- 管理后台优先适配 1024px

### 性能要求

- 首屏加载时间 < 3 秒
- 实时数据更新不造成页面卡顿
- 图表渲染使用虚拟化（大数据量时）

---

## 代码规范

- 单个组件不超过 **200 行**（超过必须拆分）
- 单个文件不超过 **400 行**
- Props 必须有明确的 TypeScript 类型定义
- 必须处理加载状态和错误状态

---

## Git 提交规范

### 前端专用 Scope

| Scope | 用途 |
|-------|------|
| `ui` | UI 组件变更 |
| `page` | 页面变更 |
| `hook` | 自定义 Hook 变更 |
| `style` | 样式变更 |
| `store` | 状态管理变更 |

### 示例

```
feat(ui): 添加设备卡片组件
fix(chart): 修复时序图实时更新闪烁问题
style(dashboard): 优化仪表盘布局和配色
refactor(hook): 重构 useRealtimeStatus 支持自动重连
```

---

## 原型验收标准

在写前端代码之前，原型必须满足：

- [ ] 使用真实数据结构（不用 lorem ipsum）
- [ ] 展示完整交互状态（加载、空状态、错误状态）
- [ ] 响应式布局正确
- [ ] 配色方案不是蓝紫渐变等 AI 默认风格
- [ ] 用户确认满意

---

## Forbidden Patterns

- **禁止**跳过原型直接写前端代码
- **禁止**不看 Design Reference 就开始设计
- **禁止**蓝紫渐变等千篇一律的风格
- **禁止**不调用 `frontend-design` / `ui-ux-pro-max` 技能包
- **禁止**用 `any` 类型
- **禁止**在组件里直接写 API 调用
- **禁止**忽略加载状态和错误状态
- **禁止**不考虑移动端响应式
