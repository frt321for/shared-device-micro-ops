# Logging Guidelines

> IoT 项目统一日志规范

---

## 核心原则

- 使用结构化日志（JSON 格式），不要用纯文本
- 每条日志必须包含：时间戳、级别、模块、traceId
- 设备相关日志必须包含 deviceId
- 敏感信息禁止写入日志

---

## 日志级别

| 级别 | 用途 | 示例 |
|------|------|------|
| `DEBUG` | 开发调试信息，生产环境关闭 | 设备原始报文、SQL 查询 |
| `INFO` | 正常业务流程记录 | 设备上线、工单创建、充电会话开始 |
| `WARN` | 异常但不影响运行 | 设备心跳延迟、传感器数据越界 |
| `ERROR` | 错误需要关注但服务可继续 | 设备命令失败、数据库超时 |
| `FATAL` | 致命错误 | 数据库连接池耗尽、MQTT Broker 断连 |

---

## 结构化日志格式

```json
{
  "timestamp": "2026-05-03T12:00:00.123Z",
  "level": "INFO",
  "module": "device",
  "traceId": "abc-123-def",
  "deviceId": "1001",
  "message": "Device online",
  "metadata": {
    "siteId": 1,
    "deviceType": "battery_pack"
  }
}
```

---

## 必须记录的事件

### 设备生命周期

```
INFO  - 设备注册 / 上线 / 下线 / 删除
INFO  - 设备命令下发 / 命令响应
WARN  - 设备心跳超时 / 数据越界 / 重复注册
ERROR - 设备命令失败 / 协议解析错误
```

### 业务流程

```
INFO  - 工单创建 / 指派 / 处理 / 完成 / 关闭
INFO  - 规则触发 / 告警产生 / 告警恢复
INFO  - 数据导出 / 报表生成
WARN  - 工单超时 / 规则冲突
ERROR - 业务逻辑异常 / 数据不一致
```

---

## 禁止记录的内容

```
# ❌ 绝对不能记录
- 用户密码、Token、API Key
- 数据库连接字符串（含密码）
- 完整的信用卡号、身份证号
- MQTT 认证凭据

# ❌ 不应该记录
- 大量传感器原始数据（用时序库）
- 循环中的每次迭代日志（只记汇总）
```

---

## Forbidden Patterns

- **禁止**用 `console.log` / `print()` 作为日志输出（用结构化日志库）
- **禁止**在生产环境开启 DEBUG 级别
- **禁止**在日志中打印完整 SQL 语句
- **禁止**用日志替代监控指标（计数器用 Prometheus）
