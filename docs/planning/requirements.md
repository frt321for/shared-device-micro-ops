# 需求文档 — 共享设备微运营平台

## 项目背景

共享设备业务（咖啡机、零食柜、洗衣机、自提柜、共享冰箱）运营方关心的是设备有没有缺货、有没有故障、是否漏单、是否需要补货、派谁去处理、路线怎么排、站点是否赚钱、SLA 是否达标。本项目构建一个多设备统一运营平台，通过模拟设备上报形成 "监控 → 预测 → 派单 → 处理 → 收益分析 → 调整站点" 的运营闭环。

## 用户角色

| 角色 | 职责 |
|------|------|
| 运营经理 | 查看站点收益、设备状态、补货效率、SLA |
| 补货员 | 接收补货任务、记录到场、补货数量和异常 |
| 维修人员 | 处理设备故障、回填维修结果、复测状态 |
| 仓库管理员 | 管理商品/耗材/库存/补货出库 |
| 财务人员 | 查看站点收入/损耗/异常订单 |
| AI 运营助手 | 生成补货原因、故障归因、周报、站点调整建议 |

## 核心功能需求

### F1：站点与设备管理

- 站点档案：位置、楼宇、楼层、营业时间、负责人、服务等级
- 设备档案：设备类型、编号、容量、状态、所属站点
- 设备组管理：同一站点多台设备聚合监控
- 模拟设备管理：批量生成设备，配置库存消耗、故障率、上报频率

### F2：库存与耗材

- SKU 档案：规格、补货单位、保质期、成本
- 仓库库存：入库、出库、盘点、损耗
- 设备库存：当前余量、预计售罄时间、补货阈值、人工校正
- 损耗记录：过期、破损、盘亏、异常开门

### F3：故障与工单

- 故障类型：离线、卡货、缺料、温控异常、门锁异常、支付异常
- 故障分级：按影响收入、食品安全、服务中断、SLA 生成等级
- 工单流转：待生成 → 待派单 → 已派单 → 已到场 → 处理中 → 待复核 → 已关闭
- 重复故障归因聚合

### F4：补货预测与派单

- 缺货预测：按历史销量、时段、库存余量估算售罄时间
- 任务优先级：缺货风险 + 收入影响 + 距离 + SLA + 人员负载
- 路线建议：地图连线展示多站点执行顺序
- 人工调整：可修改优先级、人员、路线，保留原因

### F5：收益与 SLA

- 站点收益：收入、订单数、毛利、损耗、补货成本、维修成本
- 设备效率：可用率、售罄时长、故障时长、补货及时率
- SLA 指标：故障响应、维修恢复、缺货时长、任务完成率

### F6：AI 辅助

- 补货说明：解释为什么优先补某站点
- 故障归因：根据故障码、历史维修给出可能原因
- 周报生成：站点收益 + 缺货 + 故障 + 行动建议

## 非目标

- 不接入真实支付和资金结算
- 不接入商业地图导航接口
- 不做视觉盘点
- 不做用户小程序/会员/营销

## 验收口径

| 阶段 | 验收标准 |
|------|---------|
| 阶段 1 | 模拟多站点设备上报心跳和库存后，能在看板看到设备和库存状态 |
| 阶段 2 | 模拟设备库存低于阈值，系统能生成补货工单并关闭归档 |
| 阶段 3 | 选择多个待处理站点后，系统能给出路线建议和优先级理由 |
| 阶段 4 | 选择站点后，AI 能生成含收入/缺货/故障/建议的周报草稿 |
| 最终 | MCP 浏览器全量回归测试：每个页面元素全部点击、截图对比、网络请求验证、零控制台错误 |
