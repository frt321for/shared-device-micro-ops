# 技术决策记录

## ADR-001：设备品类范围

| 字段 | 值 |
|------|-----|
| 决策 | 多设备统一平台 |
| 选项 | 单品类起步 vs 多设备统一平台 |
| 理由 | 抽象出通用的站点/库存/工单模型，让咖啡机/零食柜/洗衣机/自提柜/共享冰箱共用同一套运营逻辑 |
| 日期 | 2026-05-15 |

## ADR-002：后端语言与框架

| 字段 | 值 |
|------|-----|
| 决策 | Java 21 + Spring Boot 3 + Maven |
| 选项 | Python FastAPI, Go Gin/Fiber, Java Spring Boot, Rust Axum |
| 理由 | 业务系统为主（站点/库存/工单/派单/收益），Spring Boot 的事务/AOP/生态匹配；JDK21 虚拟线程在 I/O 场景下不输 Go；70% 是业务逻辑编排而非纯网关 |
| 日期 | 2026-05-15 |

## ADR-003：数据库架构

| 字段 | 值 |
|------|-----|
| 决策 | 三库分离：PostgreSQL + TimescaleDB + Redis |
| 选项 | 单库 vs 三库分离 |
| 理由 | 业务事实、时序事件、实时状态三类数据特性不同，统一存储会导致性能问题。TimescaleDB 延续 PostgreSQL 生态，无保留限制 |
| 日期 | 2026-05-15 |

## ADR-004：库存模型

| 字段 | 值 |
|------|-----|
| 决策 | 双层库存（仓库 + 设备） |
| 选项 | 单层（设备直接增删库存） vs 双层 |
| 理由 | 接近真实业务，支持完整的仓库出入库、损耗、盘点流程 |
| 日期 | 2026-05-15 |

## ADR-005：AI 接入方式

| 字段 | 值 |
|------|-----|
| 决策 | ModelScope API (OpenAI 兼容格式) |
| 选项 | OpenAI API、本地 ollama、MCP Server 模式 |
| 理由 | OpenAI 兼容格式，baseurl 指向 ModelScope，国内访问稳定；模型 DeepSeek-V3.2；密钥从环境变量 MS_KEY 读取 |
| 日期 | 2026-05-15 |

| 理由 | Apache 2.0 纯开源，轻量，适合中等规模设备模拟场景 |

## ADR-009：部署方式

| 字段 | 值 |
|------|-----|
| 决策 | Aliyun Docker + SSH 隧道（端口+1） |
| 选项 | 公网暴露 vs SSH 隧道 |
| 理由 | 基础设施在云服务器 Docker 运行，本地开发通过 SSH 隧道连接，端口号加 1 避免冲突。不公网暴露容器端口 |
| 日期 | 2026-05-15 |

## ADR-010：进程管理

| 字段 | 值 |
|------|-----|
| 决策 | PowerShell 脚本管理（.ps1） |
| 选项 | 手动启动, Makefile, PS1 脚本 |
| 理由 | Windows 本地开发，PS1 原生支持进程生命周期管理（创建/停止/重启/状态查询），记录 PID，管理前后端进程 |
| 日期 | 2026-05-15 |
